# Release Readiness Matrix

Prepared by an autonomous pre-release audit pass (2026-08-16), auditing the M00-M28 build-out
plus post-M28 follow-up work against the repository/PR/CI state as actual source of truth (not
assumed from prior session summaries). Supersedes the per-item audit embedded in
`docs/RELEASE_CHECKLIST.md` — read that file for the original Release Candidate checklist and
`docs/DECISIONS.md` for the reasoning behind every entry below.

Legend: `VERIFIED` (tested against real data/a real invocation, not just unit-tested in
isolation) · `VERIFIED_WITH_LIMITATION` (real and tested, but with an acknowledged scope gap) ·
`LIVE_KEY_PENDING` (host reachable, verification script written, blocked only on a free API key
the user must register for — see `docs/HUMAN_GATE_QUEUE.md`) · `CODEX_REVIEW_PENDING` ·
`HUMAN_GATE` (blocked on a decision only a human can make) · `BLOCKED` (blocked on something
else, e.g. infrastructure not yet decided).

**A provider is never classified `LIVE_VERIFIED` on the strength of a verification script
existing.** It requires the full sequence actually having been run: live contract check → drift
compared against types/parser/schema → nullability, missing fields, revisions, units, dates and
pagination exercised → drift fixed → regression tests added → a real ingest → a re-ingest
proving idempotency → provenance verified. SEC EDGAR is the only provider that has been through
it. That run found real drift on its first attempt, which is the reason this bar exists.

## Release readiness verdict

**`RELEASE_CANDIDATE_PENDING_EXTERNAL_GATES`** — one real Codex REVISE round has already
happened and been fully addressed; the next external gate is Codex **re-review**, not a first
review.

Every task buildable, fixable, or auditable without a human decision or an external tool this
environment doesn't have has been completed:

- P0 = 0, P1 = 0 (218/218 automated tests pass against a real local PostgreSQL 16.10, up from
  209; full verify chain green, `npm run e2e` 17/17 in a real browser).
- CI green on the current PR head.
- **The 2026-08-17 local-environment round is the most important qualifier on this document.**
  Moving off the cloud sandbox onto real infrastructure falsified four previously-green results,
  including the H3 concurrency fix from the Codex REVISE round, which was itself defective and
  has been re-fixed. See `docs/DECISIONS.md`'s 2026-08-17 entry. Read every `VERIFIED` below as
  "verified in a named environment", and treat a green suite as evidence about that environment.
- Financial-data invariants (units, timezones, revisions, staleness) tested with dedicated
  regression coverage, including boundary cases added this audit pass.
- Provenance paths independently re-verified against real DB state.
- Legal guardrails tested, with known gaps documented rather than hidden.
- A deterministic Ask Market safe mode now enforces the redirect requirement without waiting for
  the LLM decision.
- Security self-review (M26) plus an independent `security-review` skill pass both completed,
  zero high-confidence findings.
- A real Codex review already ran once (local-machine path) and returned REVISE with 3 P0
  blockers; all 3 are fixed and regression-tested, plus 3 recommended P1s — see
  `docs/DECISIONS.md`. `docs/CODEX_REVIEW_PACKET.md` §0 has the scoped re-review request.

Candidate:
